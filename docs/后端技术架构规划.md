本文档合并了原《后端技术架构规划》和《后端联调接口说明》，以当前仓库 `backend/src/index.js` 的实际实现为准。

## 1. 文档范围与现状

- 线上后端地址：`http://111.229.204.242:8081`
- 健康检查：`GET /healthz`
- 后端运行入口：`backend/src/index.js`
- 容器内启动命令：`node src/index.js`（见 `backend/package.json`）

## 2. 技术架构

### 2.1 总体拓扑

```text
WeChat Mini Program
```

### 2.2 组件职责

- `Express + pg`：单体 API 服务，负责鉴权、业务逻辑、数据库读写。
- `PostgreSQL`：核心业务数据（用户、论文、行为、评论、项目截止、Lab 历史记录等）。
- `Nginx`：统一入口、反向代理、请求体大小控制、健康检查转发。
- `Redis`：容器已部署并配置 `REDIS_URL`，但当前代码未引入 Redis 客户端。

## 3. 代码组织与实现方式

当前后端是“单文件服务”实现（`backend/src/index.js`），主要通过“工具函数 + 路由分组”组织：

- 认证与用户：微信登录、邮箱登录注册、资料更新。
- Papers：论文流、详情、阅读行为、收藏、评论、AI 阅读。
- Projects：会议截止卡片 CRUD。
- Profile：仪表盘统计。
- Lab：AcademicPls、Citations、DataViz、Review Simulator。

关键实现特征：

1. 鉴权使用 JWT，默认有效期 `7d`。
2. Paper Feed 主源为 OpenAlex，失败时回退本地缓存。
3. LLM 调用统一经 `requestLlmCompletion`，模型池串行重试。
4. DataViz / Review 异步任务状态保存在内存 `Map`，TTL 为 2 小时。
5. `user_profile_settings` 表由代码在运行时按需 `CREATE TABLE IF NOT EXISTS`。

## 4. 核心业务实现细节

### 4.1 认证与用户

- `POST /auth/wx-login`
  - 使用 `code2session` 获取 `openid`，按 `openid` upsert 用户。
- `POST /auth/email-register` / `POST /auth/email-login`
  - 使用 `scrypt` 存储和校验密码哈希。
- `PUT /users/me/profile`
  - 支持更新：`nickname`、`avatarUrl`、`badgeKey`、`badgeText`、`preferredLanguage`。

### 4.2 论文流与详情

- Feed：`GET /papers/feed`
  - 先调 OpenAlex，映射后写入本地 `papers`。
  - 同步返回当前用户行为态（`userAction`）与收藏态（`likedByMe`）。
  - OpenAlex 异常时回退 `loadLocalFeed`，并在 `meta` 标记 `fallback=true`。
- Detail：`GET /papers/:id`
  - 从本地 `papers` 读基础信息，再补充 OpenAlex 详情（引用数/venue/年份等）。
- AI Reading：`POST /papers/:id/ai-reading`
  - LLM 失败时返回规则化 fallback 文本，不直接报错给前端。

### 4.3 Lab 工具

- AcademicPls：文本润色，最大输入 `20000` 字符。
- Citations：引用格式化，最大输入 `12000` 字符，支持 LLM 失败回退。
- DataViz：支持 `csv/json/xls/xlsx`，生成图表结果（异步任务）。
- Review Simulator：支持 `pdf/txt/md`，生成审稿意见（异步优先，保留同步兼容接口）。

### 4.4 异步任务机制（当前实现）

- 任务创建后立即返回 `taskId`，状态初始 `PENDING`。
- 后台异步执行，状态流转：`PENDING -> RUNNING -> DONE|FAILED`。
- 状态保存于进程内存：
  - `reviewTasks: Map`
  - `dataVizTasks: Map`
- 已完成结果会写入 `lab_recent_records`（用于前端 Recent 历史）。

限制：容器重启会导致未持久化任务状态丢失。

### 4.5 文件输入与安全约束

- Review/DataViz 支持 `fileUrl` 或 `contentBase64`。
- 远程文件 URL 必须是 `https` 且域名后缀在白名单：
  - `.myqcloud.com`
  - `.tcb.qcloud.la`
- 主要上限：
  - 远程文件大小：约 55MB
  - manuscript base64 长度：约 70MB 字符

## 6. 常用接口入参（联调重点）

### 6.1 `POST /auth/email-register`

请求体：

```json
{
  "email": "alice@example.com",
  "password": "Passw0rd!123",
  "fullName": "Alice",
  "fieldOfStudy": "NLP"
}
```

### 6.2 `GET /papers/feed`

Query：

- `page`（默认 1）
- `pageSize`（默认 10，最大 30）
- `keywords`（为空时使用 `DEFAULT_FEED_KEYWORDS`）

### 6.3 `POST /papers/:id/action`

请求体：

```json
{ "action": "READ" }
```

可选值：`PASS | MARK | READ`

### 6.4 `POST /papers/:id/like`

请求体（可选）：

```json
{ "liked": true }
```

- 传 `liked`：显式设置收藏状态。
- 不传 `liked`：执行 toggle。

### 6.5 `POST /lab/review-simulator/tasks`

请求体：

```json
{
  "fileName": "draft.pdf",
  "mimeType": "application/pdf",
  "extension": "pdf",
  "fileUrl": "https://<cloud-temp-url>"
}
```

### 6.6 `POST /lab/data-viz/tasks`

请求体：

```json
{
  "fileName": "data.csv",
  "mimeType": "text/csv",
  "extension": "csv",
  "fileUrl": "https://<cloud-temp-url>",
  "chartType": "line"
}
```
