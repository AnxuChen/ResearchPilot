# Research Pilot 后端技术架构说明（当前实现，2026-02-27）

本文档描述当前仓库中已经落地的后端架构，以及基于现状的后续演进建议。

## 1. 当前落地状态

- 后端：`Node.js + Express`（ESM）
- 数据库：`PostgreSQL`
- 缓存：`Redis`（当前主要用于部署标准化，任务状态仍以内存 Map 为主）
- 网关：`Nginx`
- 部署方式：`Docker Compose`（`api + postgres + redis + nginx`）
- 小程序接入：CloudBase AnyService 或 direct-http（运行时可切换）

## 2. 总体架构

```text
WeChat Mini Program
   |
   | request.js (Bearer / AnyService headers)
   v
CloudBase AnyService or Direct HTTP
   |
   v
Nginx (8081) -> API (Express, 3000 in container)
   |                      |            |
   |                      |            +--> LLM Provider (chat completions)
   |                      |
   |                      +--> OpenAlex API (paper feed/detail enrichment)
   |
   +--> PostgreSQL (users/papers/comments/projects/lab_recent_records/...)
   +--> Redis (预留)
```

## 3. 代码与模块分布

- API 入口：`backend/src/index.js`
- 部署编排：`deploy/docker-compose.yml`
- 反向代理：`deploy/nginx.conf`
- 数据模型：`backend/prisma/schema.prisma`

当前后端采用单体文件实现（`index.js` 约 4k+ 行），模块按“路由分组 + 工具函数”组织：

- Auth/User：微信登录、邮箱注册登录、资料设置
- Papers：Feed、详情、阅读标记、收藏、评论、AI 阅读摘要
- Projects：会议卡片 CRUD
- Profile：仪表盘统计
- Lab：
  - AcademicPls
  - Citations
  - DataViz（异步任务）
  - Review Simulator（异步任务 + 同步兼容）

## 4. 数据与外部依赖

### 4.1 数据源

- 论文流主数据源：OpenAlex
- OpenAlex 失败时回退本地缓存 `papers` 表

### 4.2 LLM 调用

- 统一通过 OpenAI 兼容 `/v1/chat/completions` 端点调用
- 模型池串行重试（非并发）
- 默认模型池（代码默认）：`gpt-5.2-chat-latest,minimax-m2.5,gpt-5`
- 默认 Base URL（代码默认）：`https://api.chatanywhere.tech/`

## 5. 核心数据库对象（按当前代码）

- `users`
- `user_profile_settings`
- `papers`
- `paper_summaries`
- `user_paper_actions`
- `paper_likes`
- `comments`
- `comment_likes`
- `project_deadlines`
- `lab_recent_records`
- `missions` / `tasks` / `user_badges`（用于 profile/dashboard 统计）

具体字段与索引以 `backend/prisma/schema.prisma` 为准。

## 6. 关键业务流程

### 6.1 登录

1. 小程序获取登录态（微信 code 或邮箱密码）
2. 后端签发 JWT（7 天）
3. 前端后续请求携带 `Authorization: Bearer <token>`

### 6.2 论文流

1. `/papers/feed` 接收关键词和分页
2. 优先查询 OpenAlex
3. 映射并 upsert 到本地 `papers`
4. 返回用户行为态（`userAction` / `likedByMe`）
5. OpenAlex 异常时回退本地缓存

### 6.3 Lab 异步任务（DataViz / Review）

1. 前端上传文件到云存储并拿临时 URL
2. 调用创建任务接口（返回 `taskId`）
3. 轮询任务状态接口直到 `DONE/FAILED`
4. 完成后写入 `lab_recent_records`

## 7. 当前限制与已知风险

1. DataViz/Review 异步任务状态使用进程内 `Map` 保存（容器重启后任务状态丢失）。
2. 后端单文件体量较大，后续维护成本上升。
3. LLM 接口耗时受外部模型服务影响，慢请求可能导致客户端超时。
4. Redis 已部署但未承担任务队列/持久化状态职责。

## 8. 演进建议（按优先级）

1. 将异步任务状态从内存迁移到 PostgreSQL 或 Redis 队列（BullMQ）。
2. 拆分 `backend/src/index.js` 为路由模块与 service 层。
3. 增加结构化日志与请求 ID（便于定位超时与回退链路）。
4. 为 LLM 接口补充细粒度超时与熔断策略（分工具配置）。
5. 补充自动化测试（至少覆盖 auth、papers、projects、lab 基础路径）。
